# Contributing to Lynx 🦊

First off: **thank you** for considering contributing!  
We welcome contributions of all kinds — bug fixes, improvements, documentation updates, new features, etc. Your help makes this project stronger.

---

## What we’re looking for  
We appreciate all contributions — whether you want to:  
- Fix a bug or regression  
- Improve test coverage or documentation  
- Suggest or implement a new feature  
- Clean up code, refactor modules, or improve readability  
- Help with infrastructure (CI, build system, scaffolding)  
- Review or comment on existing issues/PRs  

If you're new to the project, check for issues tagged **`good first issue`** or **`help wanted`**.

---

## Getting started  
1. Fork the repo, then clone your fork:
   ```bash
   git clone https://github.com/<your-username>/Lynx.git
   cd Lynx
   ```  
2. Create a branch for your work:
   ```bash
   git checkout -b feature/my-awesome-change
   ```  
3. Make your changes.  
4. Ensure tests build and pass.  
5. Commit your changes, push to your fork, and open a pull request (PR) back to this repo.

### Setup & build  
Refer to the **README.md** for build instructions, dependencies, and development environment setup.  
Make sure your changes compile and maintain existing functionality.

---

## Issue reporting  
When filing an issue, please:  
- Provide a clear and descriptive title.  
- Explain *what happened*, *what you expected*, and *steps to reproduce*.  
- If applicable, include logs, error messages, or screenshots.  
- Tag issues appropriately (or suggest tags) like `bug`, `enhancement`, `feature request`.

---

## Pull request process  
When submitting a PR:  
- Base it on your branch created from `main`.  
- Include a descriptive title and summary of changes.  
- Reference the issue number if your PR resolves one (e.g., “Fixes #123”).  
- Keep changes focused; avoid large sweeping modifications unless justified.  
- Write meaningful commit messages—see our [commit style guide](#coding-style--guidelines).  
- Wait for review. Maintain polite and constructive conversations.  
- Once approved and CI is green, a maintainer will merge your PR.

---

## Coding style & guidelines  
- Language: C++20 (or specified version).  
- Follow existing naming, formatting and documentation conventions.  
- Public headers must include Doxygen‑style comments.  
- Commit messages should be in imperative mood, start with a capital letter, and be < 50 characters for subject line.  
- Keep the first line of the commit message concise; optionally add a body for more detail.  
- Include tests for new functionality when possible.
